# 资料结构与覆盖范围审阅

[总目录](../README.md) · [专家面试总纲](expert-interview-guide.md) · [设计图册](../01-foundations/design-atlas.md)

## 1. 审阅结论

**按技术主题组织的结构合理，但上一版的可发现性和专家层总结不足。** 八个入口提供了学习顺序，细节资料也已保留；然而设计图分散在框架目录和 RST 中，KV 存储的跨层链路没有一篇连续正文，面试入口也没有清楚区分常规基础与专家职责。

本轮补充设计图册、静态图片、KV 存储详解、LMCache/Mooncake 联合实现和 P7–P8 能力总纲。覆盖目标是**在线推理 Infra，重点 KV Cache 存储的学习、设计与面试准备**；这不等于所有 LLM Infra 方向，也不等于已经完成生产或硬件验证。

## 2. 结构边界是否合理

| 边界 | 应怎样划分 | 本次处理 |
|---|---|---|
| 基础与实现 | 共同语义在主题层，类/接口/版本在实现层 | 保持主题优先，框架用于案例和源码对照 |
| 运行时与 KV 管理 | 前者决定执行，后者管理状态与可复用范围 | 用请求运行图和完成协议连接 |
| KV 管理与对象存储 | 前者理解前缀/layout，后者理解对象和资源 | 增加连续的存储教材与联合实现章节 |
| 存储与传输 | 前者决定发布/保护，后者移动字节 | 分开讲完成条件，并保留交叉引用 |
| Serving 与 GPU 性能 | 都影响服务，但粒度不同 | 当前共处性能主题；深 kernel 工程仍是后续专项 |
| 技术主题与学习工具 | 01–06 是技术主线，07–08 是实验与能力维度 | 不把八个目录当作八层运行架构 |
| 文档源与阅读站 | 内容维护需要可审阅，阅读需要导航与展示 | Markdown/RST 为内容源，HTML 自动生成 |

已有长篇教材按主要问题归位，跨主题内容通过链接复用。旧编号和题号是定位标记，不是新课程顺序。仍有部分基础解释重叠，读者应按主题主线选读，不必重复执行专项计划。

## 4. 不能声称已经完备的部分

- **专家实践证据**：文档不能替代独立负责子系统、处理复杂故障和推进跨团队接口的经历。阅读完整不等于达到某个职级。
- **真实 GPU/RDMA 和规模验证**：提供实验方法与版本入口，不把理论下界、教学脚本或协议推演说成真实收益。
- **CUDA/kernel 深度工程**：已有性能原理和阅读入口，尚不是从编写 kernel 到质量/性能回归的完整专项课程。
- **复杂模型与并行**：MLA、滑窗、混合状态、MoE、EP 等已有边界提示和部分教材，仍需按目标模型深入，不能视为所有架构均已覆盖。
- **平台运维落地**：已有 SLO、故障、配额与演进设计；具体 Kubernetes 编排、自动扩缩容、发布流水线与安全集成仍需结合目标平台。
- **训练与其他 LLM Infra**：分布式训练、训练 checkpoint、数据平台和完整编译器工程不在这套推理主线的覆盖承诺内。

## 5. 面向专家岗位的验收门槛

至少形成一份含正常、超时、取消和故障路径的设计；一套容量、网络、元数据与成本预算；一条可以定位到源码的联合实现；一份有退化条件的实验或明确未测项的验证计划。

最关键的检查是：读者能否连续回答“为什么能复用、怎样发布、谁保护、何时完成、怎样回收、失败后怎么办、是否值得”。如果某个答案只有术语，没有状态、预算或证据，应继续补齐。

## 6. 后续维护规则

新内容先归属技术问题，再加入实现案例；新增版本事实给出固定提交；图的箭头、正文的协议和实验的验收保持一致。HTML 从原文生成，避免单独修改站点内容导致两套资料漂移。

后续优先补真实验证和专家练习的完成记录，而不是继续堆框架名称或复制题库。
