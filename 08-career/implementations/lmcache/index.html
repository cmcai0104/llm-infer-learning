跨项目学习先读 全库总目录 和 LMCache 白话介绍，按 统一学习计划 推进。 本页保留 LMCache 专题深读导航，以下 28 天安排是单项目备选。

这套资料面向希望进入 LLM 推理基础设施、KV Cache 存储与数据传输岗位的工程师。 目标是在 28 天、约 70 小时 内，从容量计算和缓存正确性出发，读懂 LMCache 主路径，解释它如何与 Mooncake 组合，并完成一份有实验依据的系统设计。 默认掌握 Python、基本 C++、操作系统与网络基础；不要求先读完 Transformer 论文。

阅读基线与边界

资料核对日期为 2026-10-26，源码基线为：

  • LMCache ff9185d419e1 （2026-10-23）：以推荐的 multiprocess（MP）独立服务模式为主。

  • Mooncake dd1217b6c461 （2026-10-23）：重点是 Store 与 Transfer Engine。

这是针对上述提交的学习资料，不代表任意 PyPI 版本的功能承诺。旧文章中的 lmcache/v1/cache_engine.py 在当前树中对应 lmcache/inprocess/v1/cache_engine.py；MP 主线使用另一组 server、module、 StorageManager 接口。实验前记录自己的提交、包版本和运行时， 并阅读 兼容性说明。

全文区分三种内容：标明源码路径的内容描述本基线实现；公式与取舍讨论是通用原理； 明确写为“教学模型”“设计建议”的内容不是 LMCache 已实现的算法。 性能数字若无实测说明，均为带假设的算例。

如何使用

单项目深读可按 专项计划 推进；先读 公共基础，再对照 知识地图 阅读源码。无 GPU 的 Mac/普通笔记本可完成容量、 前缀哈希、时延模型和源码练习；GPU 推理与 RDMA 实验需要相应 Linux 环境。 不具备硬件时，把结果明确写为“理论估算/未测”，不要填造吞吐数据。

面试准备优先读 面试问答 的 Q1–Q40，再完成 系统设计 的容量与故障设计题。 已有 Mooncake 基础者可先读 LMCache 内核，补足推理引擎与缓存之间的契约。
