08 专家能力与面试 · 专注 KV Cache 存储

SGLang 专项：28 天计划

白话导读：SGLang 单项目的 28 天计划：单机链路 → 调度与 KV 管理 → HiCache 与外部存储 → 分布式与面试。

  • 优先执行全库统一计划。
  • 文中给出了不同硬件条件下的执行方案。

每周末按“验收”小节自查。

这是 SGLang 单项目深读计划。跨项目学习优先执行全库统一计划，本表用于补充 Runtime、Radix 和 HiCache 专项任务。

返回导航 · 实验手册 · 验收标准

1. 时间安排

总周期 28 天，不超过一个月；每天 2–3 小时。

推荐分配：

  • 原理：30–45 分钟。
  • 源码：45–60 分钟。
  • 实验或复盘：45–60 分钟。

每天结束时，用五分钟记录“今天解释清楚的问题、仍未确认的假设、下一步验证方法”。源码阅读以问题为单位，不要求从头读完大文件。

第一周验收

  • 用 5–10 分钟解释从 Prompt 到输出 token 的路径。
  • 能找到 Scheduler 主循环与模型执行入口。
  • 能解释首 token 为什么通常来自 Prefill。
  • 分清客户端 TTFT、GPU Prefill 时间与 E2E。
  • 对指定模型手算每 token KV 字节数。

手工调度练习

设有 4 个请求：

请求 输入长度 输出预算 到达顺序
A 512 256 1
B 8192 64 2
C 256 128 3
D 4096 256 4

不要求复刻 SGLang 的所有细节。用一个假设的 Prefill token 预算和 KV 总容量，逐轮说明：

  1. 哪些请求运行、哪些等待。
  2. 每轮新增多少 KV。
  3. 长 Prefill 如何影响 A 的 ITL。
  4. 使用 Chunked prefill 后如何变化。
  5. 缓存容量不足时哪些空闲前缀可淘汰，哪些不能。

第二周验收

  • 区分 allocator、pool、prefix cache 和 Attention backend。
  • 正确解释节点拆分、引用保护、请求结束与缓存保留。
  • 能说明为什么某一种状态命中，不代表混合模型整体可以恢复。
  • 能从源码指出正常循环和重叠循环的主要区别。

6. 不同硬件条件下的执行方案

条件 可执行任务 限制
只有本地 macOS 阅读、图示、计算模型、源码和测试分析 本手册 CUDA/RDMA 实验需要另配环境
一张 Linux NVIDIA GPU 单机 serving、调度、GPU/CPU/外部缓存实验 跨实例可采用顺序重启；不能替代多节点网络验证
两张 GPU 增加 1P1D、多卡基础实验 同机传输不代表跨节点性能
多节点及 RDMA PD、共享缓存、网络拓扑与扩展性实验 需要记录网络、驱动、NUMA 与并行配置

没有 GPU 时，D2、D3、D9、D18、D19、D21、D23、D25 的执行部分可替换为：

  1. 阅读对应测试与官方示例。
  2. 分析已有公开 trace 或 benchmark。
  3. 完成容量和传输成本模型。
  4. 写出控制变量、测量指标与预期反例。

简历与面试必须区分“设计过”“阅读过”“模拟过”“实际运行验证过”。

7. 时间不足时的取舍

保留所有 P0：请求链路、指标、调度、KV、Radix、HiCache、Mooncake/LMCache 边界。

可以压缩 P2：不在首月深入全部多模态模型、全部 kernel 后端和 Diffusion。把一组缓存或调度实验做扎实，比同时启动很多服务却无法解释结果更有价值。

最终验收与报告模板见 09。
