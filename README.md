# LLM Infra 学习资料库

这套资料围绕一个问题展开：**怎样让大模型在有限的 GPU、内存和网络资源上，正确、稳定、低成本地服务更多请求？**

资料按 **LLM Infra 的技术问题**组织：先理解共同原理和系统取舍，再比较具体实现，最后通过实验验证。vLLM、SGLang、LMCache、Mooncake 是深入源码的案例，放在各主题内部，不作为全库的学习分区。重点方向是 KV Cache 管理、分布式存储与数据传输。

## 一、沿系统链路学习

| 主题入口 | 核心问题 | 学完应能交付 |
|---|---|---|
| [01 基础与全景](01-foundations/README.md) | 模型怎样生成 token？计算、显存、网络和延迟是什么关系？ | 请求全链路图、容量与时间算例 |
| [02 推理运行时](02-runtime/README.md) | 请求怎么排队、组成 batch、交给 GPU，再安全结束？ | 调度循环、状态机和资源所有权表 |
| [03 KV Cache 管理](03-kv-cache/README.md) | 哪些状态可以复用？如何分页、共享、分层、加载与回收？ | 正确性条件、缓存生命周期和收益模型 |
| [04 分布式存储](04-storage/README.md) | 对象存在哪里？谁能读？副本、租约、淘汰与故障怎么处理？ | Put/Get 时序、容量和故障设计 |

| [06 Serving 与性能](06-serving/README.md) | 怎样组合计算、缓存和通信，让更多请求满足 SLO？ | 部署取舍、端到端性能分析与选型依据 |

## 二、每个主题怎么读

统一采用 **问题 → 原理 → 设计取舍 → 实现对照 → 实验与验收** 的顺序。例如学习前缀缓存：

1. 先理解前缀、模型和位置等条件为什么影响 KV 正确性。
2. 再学习分页、引用、索引、淘汰和异步加载的共同约束。
3. 在同一个问题下比较 block hash、Radix、分层缓存控制等方案。
4. 最后进入 `03-kv-cache/implementations/`，对照框架源码，做一次命中、失配和失败实验。

这样更换框架后，已有知识仍能用于判断新系统的行为。框架名相同也不能替代版本、模型、布局与接口契约核对。

## 三、实际目录约定

```text
技术主题/
├── README.md                    # 共同问题、原理、取舍、阅读与验收
├── 共同专题.md                  # 不依赖某个框架的深入解释
└── implementations/
    └── 具体项目/
        └── 实现专题.md          # 当前版本的机制、源码、边界与差异
```

基础概念集中在主题层；具体类、接口、启动参数和版本限制进入实现层。跨主题长文按主要问题归属一处，其余主题引用相应章节。比如 Store 的对象生命周期属于存储，RDMA 注册和传输完成属于数据传输，二者互相链接。

## 资料使用约定

- 主线使用普通自回归、causal full-attention 模型解释机制；GQA、MLA、滑窗和混合模型会单独说明边界。
- 源码事实以[版本基线](08-career/references.md)为准，公式示例不等于实测。部署时重新核对匹配的框架、Connector、模型与后端版本。
- `implementations/` 中保存学习笔记与源码阅读路线，上游源码链接固定到相应提交。
- 原有 Markdown、reStructuredText 教材均保留。Markdown 可直接阅读；RST 中的 Mermaid、数学和 Sphinx 指令需要相应渲染支持，也可阅读源文本。统一主线使用 Markdown。
- 本机没有 GPU/RDMA 也能做推导、源码练习和 CPU 模拟。真实性能、GPU 正确性与分布式故障结论，需要在对应硬件环境中验证。
